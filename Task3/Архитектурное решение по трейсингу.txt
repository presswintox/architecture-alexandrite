1. Анализ системы в контексте трейсинга:

Потенциальные точки сбоев:
- Ошибки в бизнес-логике бекенд-сервисов. Например, заказ не сохраняется, в расчете цен и так далее.
- Ошибки в интеграции между сервисами. Например, сервис MES API не может получить данные от Shop API.
- Ошибки в работе с базами данных. Например, запросы к базе данных выполняются медленно или возвращают ошибки.

Исходя из этого, все бэкенд-сервисы (MES API, CRM API, Shop API) должны быть покрыты трейсингом. Это позволит нам отслеживать запросы между сервисами и выявлять узкие места в производительности.

2. Мотивация для трейсинга:

В текущей архитектуре отсутствует сквозная наблюдаемость: мы не можем отследить полный путь заказа от момента его создания до завершения. Это ведёт к следующим проблемам:

- Потеря заказов на стыке сервисов: если один из сервисов не может обработать заказ, мы не знаем, где именно произошла ошибка.
- Сложности при отладке инцидентов: нельзя быстро локализовать, где произошёл сбой.
- Неясность узких мест — невозможно понять, какой компонент замедляет цепочку.
- Повышенная нагрузка на поддержку — инциденты приходится разбирать вручную.

На что повлияет трейсинг:
- Хорошо для бизнеса: повысит качество обслуживания клиентов, снизит количество инцидентов и ускорит время реакции на них.
- Улучшит диагностику и отладку: сможем быстро находить и исправлять ошибки.
- Повысит стабильность системы: сможем выявлять и устранять узкие места.

3. Предлагаемое решение:
Для реализации трейсинга в нашей системе мы будем использовать OpenTelemetry + Jaeger. OpenTelemetry — это стандарт для сбора телеметрии, который поддерживает множество языков и фреймворков. Jaeger — это система для визуализации и анализа трассировок.
На схеме C4.drawio [./C4.drawio] показано, как будет выглядеть трейсинг в нашей системе. 
Каждый бэкенд-сервис будет отправлять трассировки в Jaeger, который будет собирать и хранить их. Мы будем использовать OpenTelemetry SDK в каждом из сервисов для интеграции с Jaeger.

Безопасность:
Также на схеме отображено использование VPN для доступа к Jaeger. Мы не будем делать Jaeger UI публичный доступ, он будет доступен только из внутренней сети. Это необходимо для обеспечения безопасности и защиты данных. Доступ к Jaeger будет ограничен только для разработчиков и DevOps-инженерам.

4. Компромиссы:
- Использование OpenTelemetry и Jaeger потребует дополнительных ресурсов для настройки и поддержки.
- Администрирование инфраструктуры для трейсинга может потребовать дополнительных усилий от команды DevOps.
- Повышенная нагрузка на сеть и хранилище данных из-за сбора и хранения трассировок.
