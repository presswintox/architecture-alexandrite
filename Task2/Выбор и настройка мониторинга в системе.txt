Мотивация:
- Нужен мониторинг производительности, базы данных, метрики для бизнеса.
- С помощью мониторинга сможем выявлять узкие места в системе и быстрее реагировать на проблемы.

Выбор подхода к мониторингу:
Есть несколько базовых подходов к мониторингу:
- USE (Utilization, Saturation, Errors) - подходит для мониторинга ресурсов (CPU, память, диски).
- RED (Rate, Errors, Duration) - подходит для мониторинга сервисов и приложений, особенно API.
- 4 золотых сигнала (Latency, Traffic, Errors, Saturation) - более общий подход, который включает в себя RED и USE.

Наш продукт состоит из трех приложений, каждый из которых работает на своем инстансе EC2. 

Каждый из инстансов EC2 мы будем мониторить с помощью подхода USE, так как это позволит нам получить полное представление о состоянии ресурсов и производительности каждой машины.

Сервисы MES API, CRM API и SHOP API мы планируем мониторить с подходом RED (Rate, Errors, Duration).
  - Rate: количество запросов в секунду.
  - Errors: количество ошибок (например, 5xx ошибки).
  - Duration: время ответа на запросы.
Так как они являются сервисами, которые работают с API запросами от фронтентда и внешних клиентов, то подход RED будет наиболее подходящим для их мониторинга.

Возможные метрики:
- USE:
    - CPU % for Shop / CRM / MES API
    - Memory Utilization for shop / CRM / MES API
    - Memory Utilization for shop db instance
    - Memory Utilization for MES db instance
    - Size of S3 storage
    - Size of shop db instance
    - Size of MES db instance
    - Number of connections to shop db instance
    - Number of connections to MES db instance
- RED
    - RPS for Shop/ CRM / MES API
    - RPS per user for Shop API
    - RPS per user for MES API
    - Numbers HTTP 500 for Shop / CRM / MES API
    - Response time for Shop/ CRM / MES API


План действий:
Для сбора метрик мы будем использовать Prometheus. Этот инструмент позволяет собирать, хранить и анализировать метрики, визуализировать и создавать предупреждения.
1. Поднять новый инстанс EC2 под Prometheus. Установить Prometheus при помощи Docker. В Docker образе уже есть все необходимое для работы с Prometheus: HTTP сервер, TSDM база данных и сервис, который собирает метрики с агентов по модели pull.
2. Настроить Prometheus агенты для каждого из инстансов EC2, на которых работают наши приложения. Агенты будут собирать метрики с помощью экспортеров.
2.1 Установить Node Exporter на каждый из инстансов EC2. Node Exporter будет собирать метрики с операционной системы и передавать их в Prometheus.
2.2 В зависимости от того, на каком языке написаны наши приложения, установить соответствующие экспортеры:
  - Для приложений на Shop API и CRM API использовать Micrometer.
  - Для приложений на MES API использовать Prometheus.Client.
  - Для приложений на RabbitMQ использовать RabbitMQ Exporter.
  - Для приложений на PostregSQL использовать PostgreSQL Exporter.
  - Для приложений на S3 использовать S3 Exporter.
3. Настроить Prometheus для сбора метрик с агентов. Для этого нужно будет указать адреса агентов в конфигурационном файле Prometheus.
4. Установить Grafana на инстанс с Prometheus. Grafana будет использоваться для визуализации метрик, собранных Prometheus. В Grafana можно будет создавать дашборды и настраивать алерты.
5. Настроить дашборды в Grafana для отображения метрик по каждому из приложений и баз данных. Дашборды будут включать графики с метриками USE и RED, а также алерты для быстрого реагирования на проблемы.
6. Настроить алерты в Prometheus и Grafana для уведомления о проблемах с производительностью или ошибках в приложениях.
